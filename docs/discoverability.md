# Discoverability

This file is about helping the repository get found, understood, and remembered.

## Recommended GitHub description

Use a short description that is clear, practical, and keyword-rich:

`Design patterns, templates, and starter files for long-running AI workflows with exact continuation, hard gates, and low-theater execution.`

## Good positioning sentence

If you need one sentence to describe the repository in a post or profile:

`A practical playbook for running long-lived AI workflows that can resume cleanly, validate honestly, and avoid fake progress.`

## Why this matters

This repository is not a one-click tool.

That means discoverability depends less on install commands and more on whether the right people immediately recognize the problem it solves.

The strongest discovery strategy is to make the repository easy to classify:

- it is about AI workflows;
- it is about continuity;
- it is about validation;
- it is about long-running execution;
- it is about reducing orchestration theater.

## Best sharing angles

These are strong angles for posts, conversations, and release notes:

- how to stop long-running AI workflows from faking progress
- why one primary execution thread often beats many chatty helper agents
- how to make overnight AI work resumable
- why exact handoffs are more valuable than fresh status notes
- how to keep AI workflows useful after context windows stop helping
